# Руководство администратора TrafficLens

Этот документ — для администратора, который эксплуатирует TrafficLens: учётная запись, обновление, IOC и правила, хранение, резервное копирование и диагностика. Установка с нуля описана в [installation.md](installation.md), живой захват — в [capture.md](capture.md).

## Состав развёртывания

- Контейнер `trafficlens` (Quadlet) — веб-интерфейс и анализ, порт `8080` (по умолчанию; в примерах развёртывания `8095`).
- Контейнер `trafficlens-capture` (опционально) — живой захват tcpdump с ротацией.
- Каталог данных `/data` (на хосте — например, `/home/redos/trafficlens-data`): база `trafficlens.db`, задачи `jobs/`, конфиг `config/trafficlens.yaml`, IOC `ioc/`, правила `suricata/`, спул захвата `spool/`.

## Учётная запись

Веб-интерфейс однопользовательский. Логин по умолчанию — `admin`.

```yaml
auth:
  username: admin          # или переменная окружения TL_USERNAME
  password: ""             # открытый пароль ИЛИ
  password_hash: ""        # PBKDF2-хэш (предпочтительно)
  cookie_secure: false     # true — cookie только по HTTPS (включайте за Caddy)
```

- Пароль можно передать и через `TL_PASSWORD`. Хэш вместо открытого пароля генерируется так (локально или в контейнере): `python3 -c "from trafficlens.web import hash_password; print(hash_password('НОВЫЙ-ПАРОЛЬ'))"` — учтите, что пароль попадёт в историю shell; результат запишите в `auth.password_hash`, а `auth.password` оставьте пустым.
- Если пароль не задан вовсе — авторизация отключена. Делайте так только когда доступ уже закрыт (Caddy с basic auth, изолированный сегмент).
- Rate-limit на вход: 5 неудачных попыток за 10 минут блокируют `/login` на 10 минут.

Смена пароля: отредактируйте `config/trafficlens.yaml` в каталоге данных и перезапустите сервис (`systemctl --user restart trafficlens`).

## Язык и тема

Настроек на сервере нет — каждый пользователь переключает в шапке интерфейса: **RU/EN** (cookie `tl_lang`) и **◐** светлая/тёмная тема (`localStorage`, по умолчанию — системная). Описание страниц — в [ui.md](ui.md).

## Обновление

На сервере, где развёрнут контейнер:

```bash
cd ~/trafficlens
git pull --ff-only
podman build --format docker -t localhost/trafficlens:latest .
systemctl --user restart trafficlens
bash tools/smoke_server.sh    # см. ниже
```

`tools/smoke_server.sh` — обязательная проверка после обновления: во временном каталоге (боевая база не затрагивается) загружает тестовые IOC, генерирует PCAP, прогоняет анализ, проверяет HTML/JSON-отчёты и делает healthcheck живого сервиса (`HEALTH_URL`, по умолчанию `http://127.0.0.1:8095/healthz`). Скрипт должен завершиться без ошибок; при `KEEP=1` временный каталог сохраняется для отладки.

Откат: `git checkout <предыдущий-тег>`, пересборка образа, рестарт. База и отчёты между версиями совместимы вперёд; старые отчёты можно пересобрать кнопкой «Повторить анализ».

## Индикаторы компрометации

Подробно — [iocs.md](iocs.md). Что важно администратору:

- Фиды обновляются по расписанию (`iocs.update_hours`, по умолчанию каждые 6 ч) и кнопками на странице «Индикаторы и правила».
- URLhaus / ThreatFox / MalwareBazaar требуют бесплатный Auth-Key abuse.ch: `iocs.abusech.auth_key` или `TL_ABUSECH_KEY`. Без ключа эти источники молча пустые — на странице IOC видно предупреждение.
- MISP и OpenCTI включаются автоматически, когда заданы URL и ключ (`TL_MISP_URL`/`TL_MISP_KEY`, `TL_OPENCTI_URL`/`TL_OPENCTI_TOKEN`).
- Свои списки — файлы `ioc/custom/*.txt` в каталоге данных; можно править напрямую или через веб-интерфейс. После правки файла нажмите «Обновить все».

## Правила Suricata

ET Open обновляется по расписанию (`suricata.rules_update_hours`, по умолчанию 24 ч) и кнопкой «Обновить ET Open». На странице IOC видно путь к набору правил, число правил и дату обновления. Если правил нет — сигнатурный анализ фактически не работает, проверьте доступ хоста к `rules.emergingthreats.net`.

## Хранение и очистка

```yaml
retention:
  days: 7                    # 0 — не удалять по возрасту
  max_total_gb: 0            # квота на каталог задач; 0 — без квоты
  keep_verdicts: ["critical"]  # задачи с такими вердиктами не удалять
  dry_run: false             # true — только показать, что было бы удалено
```

Очистка применяется и к загрузкам, и к захвату. Перед включением агрессивных лимитов прогоните с `dry_run: true` и посмотрите журнал.

Следите за местом: `du -sh /data/jobs`. Самые тяжёлые — извлечённые файлы (`zeek.extract_files`, лимит `extract_max_mb`).

## Резервное копирование

Достаточно копировать каталог данных при остановленном сервисе (или снапшот тома):

- `trafficlens.db` — очередь, задачи, база IOC;
- `jobs/` — отчёты, логи Zeek/Suricata, PCAP;
- `config/trafficlens.yaml` — конфигурация;
- `ioc/custom/` — свои списки.

Остальное (`ioc/` кэш фидов, `suricata/` правила) перекачивается.

## Диагностика

| Что | Как |
| --- | --- |
| Статус сервиса | `systemctl --user status trafficlens` |
| Журнал | `journalctl --user -u trafficlens -f` |
| Healthcheck | `curl -s http://127.0.0.1:8095/healthz` |
| Застрявшая задача | страница задачи → «Журнал», затем «Повторить анализ» |
| Движки «не найдены» | на странице «Анализы» блок «Движки»: образ собран без Zeek/Suricata — пересоберите |

Типичные ошибки установки и анализа разобраны в [troubleshooting.md](troubleshooting.md).
