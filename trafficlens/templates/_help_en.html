Administrator guide

TrafficLens dissects a traffic capture (PCAP) and shows what to look for: matches against indicators of compromise (IOCs), Suricata signature hits, transferred files, anomalies, and the compromise chain. Below is the typical workflow — from uploading a capture to a ticket-ready report.

1. Signing in

  1. Username (default admin, set via auth.username / TL_USERNAME).
  2. Password. After 5 failed attempts within 10 minutes, sign-in from that address is temporarily throttled.
  3. Sign-in button. Interface language (RU/EN) and theme (◐) can be switched in the header of any page.

2. Uploading a capture and searching jobs

  1. Upload zone: drag a PCAP/PCAPNG file here or click to browse. Analysis starts automatically.
  2. PCAP filter (expands below the upload zone): a BPF expression (tcpdump syntax) and/or a time window — only matching traffic is analyzed, which speeds up large captures considerably.
  3. Job search: matches the file name and, for finished analyses, also hosts, IOCs, transferred files and DNS names from the report.
  4. Job list with verdicts: critical / suspicious / clean. Click a row to open the report.

3. Report: verdict and actions

  1. Scored verdict: a sum of weighted findings with a breakdown showing how many points each one contributed. Confidence badges: Fact — directly observed in logs (IOC, signature, captured data), Heuristic — a statistical estimate, false positives are possible.
  2. Actions: download the standalone HTML, PDF, JSON, or the source PCAP; re-match IOCs (without re-parsing), re-run the analysis, delete the job.
  3. KPIs: connections, traffic, IOC hits, signatures, files.

4. Where to start the investigation

  1. Priority hosts — local hosts ranked by total risk. Start at the top. The CSV button exports the table (opens in Excel/LibreOffice).
  2. Risk reasons with confidence badges and the indicators involved.
  3. The ▸ icon next to an address opens its host card: a timeline of all events, contacts, files.
  4. MITRE ATT&CK panel: tactics and techniques; links lead to attack.mitre.org with a description of each technique.

5. Indicators of compromise (IOC tab)

  1. All matches against IOC feeds: type, value, sources, confidence, observation contexts, hosts.
  2. Table filter (substring). Most report tables have the same filter.
  3. Export the section to CSV.
  4. The ⋯ button — finding markup: “Confirmed” / “False positive” / “Ignored”, or add to the global allowlist. False positives and allowlisted findings stop affecting the verdict — the report is rebuilt automatically. Right-click a value to copy it or check it on VirusTotal.

The “Signatures”, “Files”, “Network activity”, “DNS”, “HTTP”, “TLS” and “Anomalies” tabs work the same way: grouping, filter, CSV, markup.

6. Network connections graph

  1. Local hosts on the left, external addresses on the right; IOC addresses are highlighted in red. Edge width depends on traffic volume.
  2. Zoom: mouse wheel (zooms to the cursor) or the −/⟲/+ buttons; drag the background to pan, drag nodes to untangle edges.

7. Compromise chain

  1. Findings laid out across MITRE ATT&CK attack stages in chronological order: recon → initial access → … → exfiltration → impact. Hosts seen on multiple stages are grouped in a separate block.
  2. Ticket-ready chains: prepared lines “host → indicator → address:port → file → hash → IOC sources” with a copy button — paste them into a ticket or an e-mail as is.

8. Indicators and rules

  1. Update IOC feeds (abuse.ch URLhaus/ThreatFox/Feodo/MalwareBazaar, MISP, OpenCTI) and Suricata rules (ET Open) with one button. The automatic update schedule is set in the config.
  2. Additional rule sources: your own rule-set URLs (ET Pro, abuse.ch SSLBL, internal .rules).
  3. Custom IOC lists: text files in the data directory; can be added right from the page.
  4. Allowlist: indicators, signatures and heuristics excluded from the verdicts of all jobs.

After updating the feeds, open the job and click “Re-match IOCs” — matches are refreshed without re-parsing the capture.
